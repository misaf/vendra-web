# Provisioning lifecycle

<Lede>
  The controller turns Laravel's desired storefront state into a running,
  healthy Compose project. This page explains that lifecycle and who owns each
  step; the API Reference owns the wire contract.
</Lede>

<Tag tone="emerald">Controller behavior</Tag> <Tag>Serialized mutations</Tag>

## Ownership boundary

<DefList
  items={[
    {
      term: 'Laravel',

    },
    {

## Storefront request lifecycle

<Steps
  items={[
    {
      title: 'POST /v1/storefronts',
      body: 'Laravel’s queued job sends the request with its bearer token.'
    },
    {
      title: 'Validate identity and schema',
      body: 'Request identity must match the encoded configuration exactly.'
    },
    { title: 'Render property', body: 'Write the per-property Compose project.' },
    { title: 'Pull image', body: 'Unless no_pull is set.' },
    {
      title: 'compose up --wait',
      body: 'Wait for the container to report healthy.'
    },
    {
      title: 'Respond',
      body: 'Return status, controller reference, and resolved image digest.'
    }
  ]}
/>

The currently accepted template family is `vendra-storefront-florist`. A
request can select a different compatible image digest per property. Property
and certificate mutations are serialized so concurrent requests cannot rewrite
the same controller state.
