# Provisioner API

<Lede>
  An internal, bearer-authenticated HTTP API with three endpoints. It is not a
  public API and must stay on an internal Docker network.
</Lede>

<Tag tone="emerald">Internal only</Tag> <Tag>Bearer authenticated</Tag>

## Endpoints

<DefList
  items={[
    { term: 'GET /health', description: 'Process health.' },
    {
      term: 'GET /v1/capabilities',
      description: 'Supported templates and controller capabilities.'
    },
    {
      term: 'POST /v1/storefronts',
      description: 'Validate, render, start, and report a storefront.'
    }
  ]}
/>

Requests are limited to 1 MiB, and property and certificate mutations are
serialized. Bearer comparison is constant-time. Logs exclude tokens, request
payloads, and generated environment values.

## Storefront request lifecycle

<Steps
  items={[
    {
      title: 'POST /v1/storefronts',
      body: 'Laravel’s queued job sends the request with its bearer token.'
    },
    {
      title: 'Validate identity and schema',
      body: 'Request identity must match the encoded configuration exactly.'
    },
    { title: 'Render property', body: 'Write the per-property Compose project.' },
    { title: 'Pull image', body: 'Unless no_pull is set.' },
    {
      title: 'compose up --wait',
      body: 'Wait for the container to report healthy.'
    },
    {
      title: 'Respond',
      body: 'Return status, controller reference, and resolved image digest.'
    }
  ]}
/>

The currently accepted template family is `vendra-storefront-florist`. The
request can still select a different compatible image digest per property.

## Authentication

The token used by Laravel must match `VENDRA_PROVISIONER_TOKEN` in the
controller environment.

<Callout type="error">
  Keep this API on an internal Docker network. It exposes container creation and
  is not designed to face the public internet.
</Callout>
