# Production host

<Lede>
  A production install pins every image by digest, keeps secrets out of YAML,
  and treats `stack up` as a convergent operation you can re-run safely.
</Lede>

## 1. Prepare infrastructure

Install Docker Engine, Docker Compose v2, and a versioned `vendra` CLI binary.

The binary is not committed to the controller repository. Build it from a
checkout during development, then install it:

```bash
mkdir -p bin
go build -o ./bin/vendra ./cmd/vendra
sudo install -m 0755 ./bin/vendra /usr/local/bin/vendra
```

Production hosts should use a versioned release artifact built for the host
platform, rather than requiring Go or a source checkout on the server.

Confirm both dependencies before deploying:

```bash
vendra version
docker compose version
```

<Callout type="warning">
  `command not found: vendra` means the binary has not been built or installed,
  or its directory is not on `PATH`. It is not created by `vendra init` or by
  Docker Compose.
</Callout>

If images come from a private registry, authenticate first:

```bash
docker login ghcr.io
```

## 2. Controller configuration

Create `/etc/vendra/controller.yaml` using immutable image digests:

```yaml filename="/etc/vendra/controller.yaml"
state_dir: /var/lib/vendra
base_domain: example.com
network: traefik-public
listen: :8080
health_timeout: 2m
certificate_mode: acme
acme_email: ops@example.com
images:
  platform: ghcr.io/your-org/vendra@sha256:PLATFORM
  website: ghcr.io/your-org/vendra-website@sha256:WEBSITE
  storefront: ghcr.io/your-org/storefront@sha256:STOREFRONT
  provisioner: ghcr.io/your-org/vendra-controller@sha256:PROVISIONER
```

## 3. Secrets

Place `APP_KEY`, database credentials, mail settings, and
`VENDRA_PROVISIONER_TOKEN` in `/etc/vendra/controller.env`, owned by root with
mode `0600`:

```bash
sudo mkdir -p /etc/vendra
sudo chown root:root /etc/vendra/controller.env
sudo chmod 0600 /etc/vendra/controller.env
```

<Callout type="error">
  Never put secrets in `controller.yaml`. It is not treated as a secret file.
</Callout>

## 4. Initialize and verify

```bash
sudo vendra init --config /etc/vendra/controller.yaml
sudo vendra stack up --config /etc/vendra/controller.yaml
sudo vendra stack status --config /etc/vendra/controller.yaml
sudo vendra stack urls --config /etc/vendra/controller.yaml
```

Re-running `stack up` is the normal convergent operation after configuration or
image changes — it is not a repair command.
