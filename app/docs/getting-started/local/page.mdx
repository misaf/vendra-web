# Local development

<Lede>
  Run locally built images behind the same Traefik topology used in production.
  Use explicit local tags and disable controller pulls.
</Lede>

## 1. Build images

```bash
docker build -t vendra-controller:local ./vendra-controller
docker build -t vendra-storefront-florist:local ./vendra-storefront-florist
docker build -f vendra-platform/docker/Dockerfile -t vendra-platform:local ./vendra-platform
```

## 2. Configure the controller

```yaml filename="controller.local.yaml"
state_dir: /absolute/writable/path/vendra-state
base_domain: vendra.test
network: traefik-public
certificate_mode: self-signed
images:
  platform: vendra-platform:local
  website: ""
  storefront: vendra-storefront-florist:local
  provisioner: vendra-controller:local
no_pull: true
```

Tags rather than digests are correct here: a digest pins an image that only
exists in a registry. Production still pins by digest.

<Callout type="warning">
  `no_pull: true` is the configuration form of `--no-pull`, and it is the only
  one the provisioner obeys. Console-driven deployment does not go through the
  CLI — the console calls the provisioner, which runs as a container and has no
  flags. Without this key it tries to pull the storefront image and the
  deployment lands in `storefront_deployments` as `failed` with a bare
  `provisioning failed`. The registry error appears only in
  `vendra stack logs provisioner`.
</Callout>

Image names must match what you built **exactly**. A registry-shaped name such
as `ghcr.io/misaf/vendra:local` is a different image from `vendra-platform:local`
even with identical contents. Check `docker images` before starting; a mismatch
reads as *No such image*.

## 3. Start and resolve hosts

```bash
vendra init --config ./controller.local.yaml
vendra stack up --no-pull --config ./controller.local.yaml
sudo vendra stack hosts --write --config ./controller.local.yaml
```

## 4. Accept the storefront certificate

Open `https://<slug>.vendra.test` and accept its certificate warning. Browser
data reads stay on that origin and pass through `/api/proxy/*`; the storefront
container connects to `api.vendra.test` and trusts the generated authority
through `NODE_EXTRA_CA_CERTS`.

    },
    {
      title: 'Verify /api/proxy requests',
      body: 'They should stay on the storefront origin and return API data through the container.'
    }
  ]}
/>

<Callout type="error">
  Do not work around server-side API certificate failures by disabling TLS
  verification. Confirm that the property container mounts `certificates/` and
  receives `NODE_EXTRA_CA_CERTS=/certs/ca.pem`.
</Callout>

Accepting the storefront warning needs no administrator rights — the exception
is stored in your browser profile. Chrome sometimes needs a hard reload before
retrying requests that already failed.

Certificates are re-signed from a persistent authority (`certificates/ca.pem`),
so the browser exception for a property survives re-renders. Only deleting
`ca.pem` or `state_dir` invalidates it. Exceptions are per browser profile and
hostname, so a new property, profile, or teammate must accept its own storefront
hostname.

### Optional: trust the authority outright

With administrator rights, install the authority and see no warnings at all.
This is a convenience, not a prerequisite — it is the same certificate either
way.

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  /var/lib/vendra/certificates/ca.pem
```

Quit and reopen the browser afterwards: Chrome and Safari cache TLS decisions
for the life of the process.

## Caveats

<DefList
  items={[
    {
      term: '--no-pull is not --pull never',
      description:
        'It skips the explicit compose pull only. Public dependencies (mysql, redis, traefik) are still fetched from a registry, which is deliberate — forbidding that would break a first run on a clean machine.'
    },
    {
      term: 'Stale local tags are used silently',
      description:

    },
    {

      description:
        'With this empty, nothing serves the apex base domain. Only property and platform hosts respond.'

  ]}
