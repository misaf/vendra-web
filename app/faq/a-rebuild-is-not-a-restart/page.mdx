# “I changed the variable and restarted — why is it still wrong?”

<Panel title="The question">
  Some version of this arrives most weeks:

  > I updated the environment value, restarted the container, and the storefront
  > is still showing the old one. Is the restart not picking up the file?
</Panel>

The restart worked. The value in the file is correct. The storefront still shows
the old one, and nothing is broken.

The distinction that matters is **when** a value is read. Some are read when the
container starts, and a restart is enough. Others are read when the image is
*built*, and by the time a container starts, they are no longer variables at
all — they have been compiled into the JavaScript that ships to the browser.

## How to tell which one you have

Look at the prefix. Anything beginning `NEXT_PUBLIC_` is destined for the
browser, and anything destined for the browser has to be in the bundle the
browser downloads. That bundle is produced once, by `next build`.

So the test is not "did I restart", it is "did a build run after my change".

## Why it is like this

This comes up often enough that people ask whether it could just read the file
at runtime instead. It could — for server-side values, it already does. But a
`NEXT_PUBLIC_` value is one the *browser* needs, and the browser never reads
your container's environment. Something has to put the value into the JavaScript
before it is served, and that something is the build.

Runtime property identity and branding do not use this mechanism: they stay
server-side and reach the container through `STOREFRONT_CONFIG_BASE64`.
