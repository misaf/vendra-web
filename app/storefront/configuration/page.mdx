# Property configuration

<Lede>
  Production injects a base64-encoded JSON object as `STOREFRONT_CONFIG_BASE64`.
  A production container refuses to run without it.
</Lede>

<Callout type="error">
  The refusal is deliberate. Falling back to the bundled example configuration
  could serve another tenant’s branding on a live domain.
</Callout>

## Required shape

```json filename="property.json"
{
  "slug": "acme",
  "theme": "default",
  "domain": "shop.example.com",
  "siteUrl": "https://shop.example.com",
  "name": { "en": "Acme", "fa": "آکمه" },
  "businessType": "Florist",
  "priceCurrency": "IRR",
  "address": { "locality": "Tehran", "country": "IR" },
  "contact": {
    "mobilePhone": "09120000000",
    "officePhone": "02100000000",
    "email": "hello@example.com",
    "hoursOpen": "08:00",
    "hoursClose": "21:00",
    "mapQuery": "35.7,51.4"
  },
  "social": {
    "whatsappPhone": "+989120000000",
    "telegramUsername": "acme",
    "instagramUsername": "acme"
  }
}
```

Optional fields include `ogImage`, `heroImage`, `aboutImage`, `messages`,
`checkout`, `currency`, and `trustSeal`. Runtime messages are deep-merged over
the brand-neutral base catalog, per locale.

Generate a configuration with:

```bash
npm run property:config <slug> -- --json
```

<Callout type="error">
  Never place secrets in `NEXT_PUBLIC_*`. Next.js inlines those values into
  client assets, where anyone can read them.
</Callout>
