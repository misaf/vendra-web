### Reaching the dashboard

`api.insecure` is enabled, which serves the API and dashboard on their own
entrypoint without a router. That alone exposes nothing: Compose publishes the
port on loopback.

```bash
# Locally — the trailing slash is required
open http://127.0.0.1:8080/dashboard/

# On a server
ssh -N -L 8080:127.0.0.1:8080 user@your-host
```

`TRAEFIK_DASHBOARD_BIND_ADDRESS` and `TRAEFIK_DASHBOARD_PORT` override the
mapping.

<Callout type="error">
  Widening the bind address publishes an **unauthenticated** dashboard on that
  interface, exposing routers, services, and certificate state. If it must be
  reachable without SSH, add a router for `api@internal` behind a `basicAuth`
  middleware and TLS, and leave this bound to loopback.
</Callout>

### Reaching MySQL

Locally, connect straight to `127.0.0.1:3306`. On a server, forward the port
rather than exposing the database:

```bash
ssh -N -L 3306:127.0.0.1:3306 user@your-host
```

The tunnel terminates on the host and dials its loopback, so one bind serves
both cases and no firewall rule is needed. `MYSQL_BIND_ADDRESS` and `MYSQL_PORT`
override the mapping when `vendra init` runs — widen only with a deliberate
reason and a firewall in front:

```bash
MYSQL_BIND_ADDRESS=0.0.0.0 vendra init --config /etc/vendra/controller.yaml
```

## TLS and headers

Public deployments use ACME. Local deployments use a persistent generated CA.

`dynamic/middlewares.yml` defines two header middlewares. Both set
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and
`Referrer-Policy: strict-origin-when-cross-origin`. They differ only in HSTS
scope.

| Middleware | Attached to | `includeSubDomains` |
| --- | --- | --- |
| `security-headers-platform@file` | `api` and `panels` routers | yes |
| `security-headers@file` | storefront property routers | no |

Customer domains get the variant **without** `includeSubDomains` deliberately.
Vendra serves one host on a domain it does not own; forcing HTTPS onto every
subdomain of that domain could break a customer's unrelated hosts, and that is
not Vendra's decision to make. Platform hosts all sit under `BASE_DOMAIN` and
are all served by this stack, so subdomain inclusion is safe there and covers
the per-tenant `<slug>.admin.<base>` panels.

### HSTS depends on certificate mode

`TRAEFIK_HSTS_SECONDS` is derived from `certificate_mode`: `31536000` under
`acme`, and `0` — disabled — under `self-signed`.

<Callout type="error">
  This is not caution for its own sake. An HSTS header served with a certificate
  the browser does not trust pins the host to HTTPS *and* removes the "proceed
  anyway" bypass, so a local `.test` host becomes unreachable until the operator
  clears HSTS state by hand at `chrome://net-internals/#hsts`. Enabling HSTS
  before real certificates exist is a self-inflicted outage.
</Callout>
